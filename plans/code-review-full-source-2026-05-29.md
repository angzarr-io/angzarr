### query_stale_cascades tracks state globally instead of per-participant — *storage/bigtable (Bigtable event store)*
- **Location:** `src/storage/bigtable/event_store.rs:1349-1396`

- **Problem:** The query_stale_cascades implementation incorrectly tracks cascade staleness at the cascade_id level instead of per-participant (domain, edition, root) level. According to the trait specification, a cascade should be considered stale only if at least one uncommitted row is older than the threshold for a SPECIFIC PARTICIPANT that has no committed cascade row. The current implementation marks the entire cascade as not-stale if ANY participant has a row newer than the threshold, which violates the per-participant semantics specified in the trait docs.
- **Fix:** Refactor to track stale state per (cascade_id, domain, edition, root) tuple instead of per cascade_id. Change the HashMap key from String (cascade_id) to (String, String, String, Uuid) to track state per-participant. For each participant, only mark it as 'all_before_threshold=false' if that specific participant has an event newer than the threshold. When collecting results, return cascade_ids where at least one participant meets the stale criteria (uncommitted, old, unresolved).
- **Verification (high):** Code analysis confirms the defect. The Bigtable implementation (lines 1349-1396) uses `HashMap<String, CascadeState>` keyed only by cascade_id, discarding (domain, edition, root) information at line 1357-1360. The cascade index row key is `{cascade_id}#{domain}#{edition}#{root}#{sequence}`, but only cascade_id is extracted and used as the state key. When processing multiple participants (different roots) with the same cascade_id, line 1382-1383 sets `has_committed=true` globally if ANY participant has a committed event, causing the entire cascade to be excluded from results even if other participants are unresolved and stale. The trait spec (lines 290-302 of event_store.rs) explicitly states 'per-participant' resolution: a cascade is stale iff at least one unresolved (cascade_id, domain, edition, root) tuple has an uncommitted event older than threshold. The Postgres implementation (src/storage/postgres/event_store.rs) uses `NOT EXISTS` with an explicit join on `(domain, edition, root)` to enforce per-participant semantics. The mock implementation (src/storage/mock/event_store.rs) tracks `HashSet<(String, String, String, Uuid)>` for resolved_participants. The fix requires changing the state key from `String` to `(String, String, String, Uuid)` and updating line 1385-1386 logic to only set `all_before_threshold=false` for the specific participant, not globally.
